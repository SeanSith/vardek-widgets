# Agent Control Widget

One panel to see and steer every AI agent on this Mac from the Xeneon Edge:

| Column | What it shows | What a tap does |
|---|---|---|
| **Desktop apps** | Claude, ChatGPT/Codex, Cursor, Antigravity, Grok Bot, LM Studio, Warp… (auto-detected) with running / frontmost state and the real app icon | Tile → open / bring to front · **×** → quit |
| **Agent sessions** | Every [agent-deck](https://github.com/asheshgoplani/agent-deck) session, live ones first (waiting = amber pulse, running = green, idle = blue), with a peek at the last lines of its tmux pane — i.e. *what the agent is asking* | **⏎ Approve** (sends Enter) · **⎋** (Escape / interrupt) · **⌨** open in Terminal · **↻** restart · **■** stop · **▶ Start** on stopped sessions · **Agent Deck** opens the TUI |
| **CLI processes** | Claude Code / Codex / Grok / Muse / OpenCode / Amp … processes running outside agent-deck, with cwd and uptime | read-only |
| **Buttons** | Your own Macro Pad buttons (this widget replaces the stock Macro Pad, see below) | runs that action |

Sizes: **8×2** full console · **5–6×2** console with narrower columns · **4×2** apps + sessions · anything smaller (2×1 … 3×2) behaves exactly like the stock Macro Pad button grid.

---

## Why this widget's id is `com.vardek.macro-pad`

Vardek widgets are sandboxed iframes: no file access, no localhost, and its proxy refuses every internal address. The only sanctioned way for a widget to *do* something is Vardek's **actions** system (owner-authored `open` / `shell` / `applescript` entries in `config.json`), and the dashboard runtime only accepts action requests from the widget whose id is `com.vardek.macro-pad`. Vardek lets a user widget shadow a bundled one, so this widget ships under that id and is a **strict superset** of the stock Macro Pad: same `Buttons` and `Button columns` settings, same button grid at small sizes, plus the console.

Delete this folder and rescan (or restart Vardek) to get the stock Macro Pad back.

## How control works

```
tap ─▶ Vardek.runAction("agentctl.ad.enter.<sessionId>")
     ─▶ dashboard runtime ─▶ EdgeDaemon POST /api/actions/<id>/run
     ─▶ config.actions[id].command  =  python3 agentctl.py run ad.enter "<sessionId>"
     ─▶ tmux send-keys -t <session> Enter
```

`agentctl/agentctl.py serve` (a KeepAlive LaunchAgent) does two things every ~5 s:

1. **Status** → writes `data.js` next to `index.html` (the widget script-loads it every 4 s). Sources: `ps` + `lsappinfo` for apps, `agent-deck list --json` + `tmux ls` + `tmux capture-pane` for sessions, `ps`/`lsof` for CLI processes.
2. **Actions** → keeps a generated, allow-listed set of `agentctl.*` actions in Vardek's `config.actions` (your own actions are preserved untouched). One fixed command per (verb, target); the runner accepts only these verbs: `app.focus`, `app.quit`, `ad.start|stop|restart|enter|esc|open`, `tui`, `refresh`. Nothing arbitrary can be passed in from the panel.

After any action the runner pokes the loop, so the panel reflects the change within a second or two.

### Start it

```
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.kevin.agentctl.plist
```

Then quit and relaunch Vardek once (the dashboard only reads its widget library at boot). Logs: `~/Library/Logs/agentctl.log`. Stop with `launchctl bootout gui/$(id -u)/com.kevin.agentctl`.

Manual runs: `agentctl.py setup` (re-detect apps / icons), `agentctl.py collect` (print status), `agentctl.py sync` (write data.js + sync actions once), `agentctl.py run <verb> <target>`.

## Configuration — `agents.json`

Generated by `setup`, safe to edit:

- `apps[]` — `key`, `name`, `path`, `bundleId`, `icon`, `emoji`, `enabled`. Set `"auto": false` on an entry to stop setup from touching it; add your own entries the same way.
- `terminal` — `"Terminal"` (default) or `"iTerm"`; used by ⌨ Open and the Agent Deck button.
- `processes` — which CLI agents to list (`claude`, `codex`, `grok`, `muse`, `opencode`, `amp`, `gemini`, `aider`, `crush`).
- `pollSeconds` — status interval (default 5).
- `bin` — resolved paths to `agent-deck` and `tmux`.

Widget settings (Admin → Widgets → Agent Control): **Layout** (auto / console / buttons), **Show live CLI processes**, **Show stopped agent-deck sessions**, plus the Macro Pad's **Buttons** and **Button columns**.

## Touchscreen: stale-geometry watchdog

The [MacXeneonEdgeTouchDriver](https://github.com/ajvwhite/MacXeneonEdgeTouchDriver) reads the Edge's position in the macOS display arrangement **once**, when the panel's HID (re)connects, and caches it. After a sleep/wake or replug it can latch onto a transient `(0,0)` before macOS restores the real arrangement — and then every tap warps the cursor to your **main** display and clicks there, so taps on the panel appear to do nothing.

`agentctl serve` guards against this: each poll it compares the driver's last-resolved origin (from its log) against the panel's live CoreGraphics origin (via the bundled `agentctl/edge-geom` helper) and, when they diverge, restarts the driver's LaunchAgent (`launchctl kickstart -k gui/$UID/com.ajvwhite.MacXeneonEdgeTouchDriver`, throttled to once per 30 s). Disable with `"touchWatchdog": false` in `agents.json`. Check it by hand with `agentctl.py touch` (prints `panel:` vs `driver:` origins and kicks if needed).

If taps ever stop working: `agentctl.py touch` — if the two origins disagree it fixes it on the spot.

## Notes

- **Approve** sends a bare Enter to the session's tmux pane — in Claude Code that accepts the highlighted option; in Codex you may need to type `y` first. **⎋** sends Escape (interrupt in Claude Code).
- Sessions whose tmux is gone show under *Stopped* with a Start button; agent-deck reports them as `error`.
- The action catalog changes only when the set of apps/sessions changes; the loop then does a `GET`+`PUT` of Vardek's config. If you're saving in the Admin panel at that exact moment, whichever write lands last wins (the loop re-adds its actions on the next change).
- Files: `manifest.json`, `index.html`, `agents.json`, `icons/`, `agentctl/agentctl.py`, generated `data.js`/`data.json`, `.poke` (refresh trigger).
